## 五、XSS 精度收口实验（2026-08-15，决策依据）

模板 XSS 分析器（aff7251）把 XSS 召回从 5% 拉到 30%，但引入大量模板误报。做了视图→模板变量链接实验，三种模式对比：

| 模式 | TP | FP | Precision | F2 | XSS TP |
|---|---:|---:|---:|---:|---:|
| 无链接（aff7251） | 257 | 142 | 0.644 | **16.0** | 33 |
| **宽松链接（f7832ac，保留）** | 253 | 136 | 0.650 | 15.8 | 29 |
| 严格链接（本地实验） | 236 | 82 | **0.742** | 14.9 | 12 |

严格模式精度 0.742，但把漏洞仓库的模板 XSS 几乎杀光（Django CBV / 上下文变量传参链接不上），TP -21。宽松链接是平衡点（FP -6、F2 基本不变），故保留 f7832ac。模板 XSS 的"真风险 vs 安全用法"区分本质是数据流问题，其余 FP 需要 context processor / 模板 include 分析，收益递减。

## 六、本轮改进清单（相对 7.0 时代的评测报告）

**引擎核心（backend/engine/）：**

1. **v3 项目级过程间污点分析（94888b0）** — 项目级单一污点图（跨文件/跨函数）；作用域命名空间（模块,函数）前缀；return 值传播（#ret 节点 → 调用点）；调用点链接（实参→形参、self.m()/Class.m()/module.f()/from x import f）；模块属性链接（`import db; c = db.c`）；analyze() 改逐 source BFS + spread 独立 visited 集；Flask-RESTX api.payload/parse_args source。
2. **更深检测（aff7251）** — 模板 XSS 分析器（Stage 3c：`|safe` 跳过字面量、autoescape off、`<script>` 插值）；ZIP Slip 检测器（CWE-22 变体）；新 sink：os.exec*/spawn*/pty.spawn/posix_spawn、xmltodict.parse、flask.Response/django JsonResponse、os.rename/remove/unlink/makedirs、shutil.move/copy/copyfile/copytree。
3. **视图→模板变量链接（f7832ac）** — render_template/render kwargs + Django ctx dict 收集视图变量，只有视图传入的变量在模板 `|safe` 才告警；消毒函数切断链；未链接上的模板走宽松回退。
4. **参数污点 + 属性传播（1bfa6b1）** — 函数参数 = 不可信 source（self/cls 除外）；属性读取传播 obj.attr ← obj；危险组合窗口放宽（PHP 同 class 块 OR ±8 行、Python 同函数 OR ±8 行）。

**回归**: test_audit_logic.py 14 用例（含 T11 跨文件 return、T12 作用域隔离 SSTI）全部通过。

## 七、遗留缺口

- **SQL 注入（23%）**：参数化查询变体、ORM 链式调用（`.filter(name=...)` 之外的字符串拼接形态）、跨文件 ORM 配置
- **反序列化（25%）**：gadget 链建模、`yaml.load` 全形态覆盖
- **语义类（0%）**：敏感数据泄露（155 GT）、安全配置错误（112）、认证/授权（83）、越权/IDOR（83）、DoS（44）——超出静态污点框架范围，需要框架语义建模
- **"Other" 族（6.2%）**：弱模式/会话管理等 877 个 GT 的大杂烩，收益最低
- 依赖目录排除已消灭绝大多数 venv 误报；剩余 FP 主要是 GT 未标注的新发现
