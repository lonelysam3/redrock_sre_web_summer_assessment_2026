## 五、本次修复清单

**引擎核心(backend/engine/):**

1. **sinks_py.py** — 新增 VulnType:insecure_deserialization / code_injection / open_redirect / xxe / xss / ssti / hardcoded_credentials / debug_mode;新增 CWE_BY_TYPE 映射表;新增 sink:db.Cursor/db.Connection.execute 系列、pickle/yaml/marshal、lxml/ElementTree/minidom(XXE)、flask/django/fastapi redirect、open/Path/send_file/FileResponse(路径穿越)、render_template_string/jinja2( SSTI)、Markup/HttpResponse(XSS)。
2. **python_scanner.py** —
   - 局部类型推断 `_build_local_types`:conn = sqlite3.connect()/pymysql.connect() 等 → db.Connection;cur = conn.cursor()(含 with 语句)→ db.Cursor → 游标 execute 命中 sink(**SQLi 从 0 召回起飞**);
   - dict 下标 source:`request.args['x']` / `request.GET['x']`(Subscript 节点 + 确定性匿名变量名);
   - 属性型 source:`request.data` / `sys.argv` 等(之前完全没生效);
   - source 后缀匹配(支持 request 是函数参数的 Django 写法);
   - sink 后缀回退:DB 命名变量 execute 系列 + session.execute + objects.raw;
   - dict 访问污点传播:`x = data.get('k')` / `x = d['k']` 从已污染 dict 传播;
   - subprocess 列表形式豁免(无 shell 不构成注入);
   - SKIP_DIRS 增加 vendor;
   - 每条发现输出标准 `cwe` 字段(eval/exec/compile 细分为 CWE-94)。
3. **sources_py.py** — 补全 Flask request.values/cookies/headers .get+下标、Django GET/POST/COOKIES/headers .get+下标、request.get_json/get_data、urllib.parse.parse_qs/parse_qsl。
4. **pipeline.py** — 收文件排除目录扩展(venv/env/site-packages/dist/build 等,**消灭 27/31 的 venv 误报**);Stage 3/4 结果统一补 CWE;新 AST 模式映射。
5. **ast_analyzer.py** —
   - 新检测器:硬编码凭据(排除测试文件/seed 脚本/DEMO_ 常量/枚举元组/字段名常量/占位符)、调试模式(排除测试文件)、Python eval/exec/compile 组合(代码注入 CWE-94);
   - 修复组合检测 bug:原来只要单一模式出现多次就触发(如两次 eval),现在要求两种模式都在 ±8 窗口内出现。
6. **call_graph_analyzer.py** — eval/exec/compile 标注为 code_injection(CWE-94)而非 CWE-78;新增 pickle/XXE/redirect/SSTI 内联 sink 模式;移除 `.execute(` 内联模式(把参数化查询误报成 SQL 注入)。

**回归**:平台自带 test_audit_logic.py 12 个用例(PHP/Python/C)全部保持原有行为,无回归。

## 六、遗留缺口(需要更大架构改动)

- **函数参数型 source**(vulnpy 库风格、vampi `get_user(username)`):需要过程间污点传播;
- **跨文件连接对象**(vulpy `import db; c = db.c`):需要模块级类型环境;
- XSS 的 HTML 模板文件分析、认证/授权/限速语义检测(设计范围外);
- dsvw 这类裸 socket 服务器(无框架 source)。
